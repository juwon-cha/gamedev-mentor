- `t8-impl-snapshot-interpolation` — 스냅샷 보간 버퍼: 원격 플레이어를 100ms 과거로 부드럽게 그리기 (실전 구현 · Medium · 실행 검증)
- `t8-interview-tcp-vs-udp` — 실시간 게임의 TCP vs UDP: 무엇을 보장받고 무엇을 직접 만들어야 하는가 (압박 면접 · Medium · 문서 대조)
- `t8-interview-prediction-reconciliation` — 권위 서버에서의 클라이언트 예측과 서버 재조정, 그리고 원격 플레이어 표시 (압박 면접 · Hard · 문서 대조)
- `t8-interview-lag-compensation-anticheat` — 지연 보상(서버 되감기)과 안티치트 기본: 클라이언트를 믿지 않는 판정 설계 (압박 면접 · Hard · 문서 대조)

**무엇을 만들었는지.** 트랙 8의 첫 6문제는 커밋 `710ddac`으로 실렸다(독립 검수 완료). 숨은 테스트가 있는 셋의 작성 단계 결과는 패킷 직렬화 8/8·0/8, TCP 프레이밍 8/8·1/8, 스냅샷 보간 8/8·0/8이었고, 면접 셋은 `tests: null`이다. 작성자는 Microsoft Learn BinaryPrimitives·Socket.Receive, Gaffer On Games 네 편, Gambetta의 Fast-Paced Multiplayer I–IV를 읽었다. Valve 위키 두 쪽은 봇 검사(403)로 열리지 않아 인용하지 않았고 Valve 고유 수치도 쓰지 않았다. 서버 검증 목록, 되감기 시간 공식과 상한, 고정 시간 간격 요구, 입력 중복, 에임봇·월핵 대책은 일반 지식으로 `sourceId`를 비워 두었다. `Write*`는 던지고 `TryWrite*`는 false를 돌려주는 동작은 로컬 .NET 8로 확인했다.

**검수에서 확인한 것.** Gaffer On Games 다섯 편, Gambetta I–IV, RFC 9293, Microsoft Learn(Socket.Receive, BinaryPrimitives), Riot의 VALORANT 넷코드와 Fog of War 글, Valve의 Bernier 논문(gamedevs.org PDF 미러)을 열었다. 무할당 테스트는 유효했다. 할당하는 TryWrite 변형 셋(byte[], string, 호출마다 encoder)은 80,000~192,000 바이트로 실패하고, 해답과 시프트+stackalloc 변형은 0이었다. TCP 프레이밍은 길이 검사를 늦게 하거나 헤더가 나뉘는 경우를 놓치는 틀린 답이 실패하고 바이트 단위 정답은 통과했다. 스냅샷 보간은 float 우선 비교·중복 허용 틀린 답이 실패했다. 틀린 답 탐침 넷은 요청 제한에 걸리기 전에 채점 서버(Compiler Explorer)에서, 나머지는 로컬 .NET 8에서 돌렸다. 코드와 테스트는 바꿀 필요가 없었다.

**틀려서 고친 것.** 직렬화는 Gambetta 원칙의 오인용과 부정확한 65535 주장을 문구만 고쳤다. TCP 프레이밍에는 RFC 9293의 바이트 스트림 인용을 더했다. 스냅샷 보간은 순서가 뒤바뀐 스냅숏 거부에 관한 채점 항목 둘에서, 기사가 이를 다루는지 확인하지 못한 Gaffer `sourceId`를 뺐다. TCP vs UDP 면접은 "30ms"를 약 33ms로 고치고, Nagle과 MTU 1472 문구를 RFC 9293과 Gaffer에 묶고, 입력 중복에 출처를 달았다. 예측·재조정 면접은 "고정 dt가 필수"를 보편 규칙처럼 썼던 것을 두 설계(VALORANT의 고정 128 Hz, 이동 코드를 공유하는 Half-Life의 `usercmd.msec`)로 바꾸고, c5·c7에 필요한 모범 답안 문장을 보탰다. 지연 보상 면접에는 실제 오류가 있었다. 되감기 양을 단방향 지연 + 보간으로 주었지만 왕복 지연 + 보간이 맞아 고쳤고, 상한·검증 목록·월핵 대책은 출처를 달거나 설계 선택으로 표시했다.

**끝까지 확인하지 못한 것.** Valve 위키와 web.archive.org가 열리지 않아 Source 엔진의 1초 되감기 상한은 인용하지 못했다. 통계적 치트 감지, 서버 리플레이, 매치메이킹·킬캠 대책, 검증 실패 처리 정책은 출처가 없어 본문에 일반적인 아이디어로 표시했다.

**무엇을 만들었는지.** IP·포트·NAT와 지연·지터·유실을 숫자로 보는 과외, 비트 단위 패킷 라이터·리더, float 좌표 16비트 양자화, 16비트 시퀀스 번호 랩어라운드 디버깅, 전용 서버·리슨 서버·P2P·릴레이 토폴로지 면접, 유실·중복·순서 뒤바뀜을 견디는 신뢰·순서 메시지 계층의 6문제다(2/2/2). 작성 단계 check-tests는 7/7·0/7, 7/7·0/7, 8/8·3/8, 8/8·0/8이었고, 과외는 `tests: null`이라 로컬에서만 돌렸다. 작성자는 Gaffer 다섯 편, RFC 1982·6298·4787·8656·9293, MS Learn 시프트·산술 연산자·Math.Round, Unity NGO 네트워크 토폴로지, Photon Fusion 호스트 마이그레이션을 읽었다. 커밋 `2f7e4f5`로 배포했다.

**검수에서 확인한 것.** RFC 6298·1982·4787·8656·9293, Gaffer 여섯 편과 State Synchronization, Unity 토폴로지·리슨 서버 페이지, Photon 호스트 마이그레이션, MS Learn 시프트·산술·Math.Round, C# 명세 §10.3.2를 열고 `extraSources`에 셋을 더했다. RTT 과외의 RFC 6298 순서, alpha 1/8, beta 1/4, 첫 표본 초기화와 인용 값(110 / 48.125 / 302.5, 바뀐 순서의 45.625)을 다시 계산해 맞았다. Gaffer 원문의 둘째 비교식이 `( s1 < s2 ) && ( s2 - s1 > 32768 )`임을 확인해 Gaffer와 RFC 1982에 대한 반 범위 진술이 맞음을 확인했다. 비트 패커(비트 순서·오버플로·끝 넘어 읽기가 시나리오에 고정)와 신뢰·순서 계층(결정적, 리스트·딕셔너리 설계 통과, 틀린 변형 여섯 실패)은 문제가 없었다.

**틀려서 고친 것.** RTT 과외의 출처 없던 keepalive "흔한 관행"을 RFC 4787 REQ-6에 묶고, 첫 표본 전 RTO(1초)와 최대값 60초 이상은 RFC 규칙이며 `maxMs` 반환은 연습 문제의 선택이라고 밝혔다. 양자화는 채점 서버에서 `(uint)NaN`이 0이라 NaN 검사가 없는 답이 통과했다. NaN 규칙을 호출자의 전제 조건으로 바꾸고 그 케이스를 뺐다. 오차 한계(15.6 mm 단계, 7.8 mm)는 맞았고 부동소수점 단서를 더했으며, "양자화된 상태로 시뮬레이션하지 말라"를 Gaffer State Synchronization으로 인용했다. 시퀀스 랩어라운드 해설은 int `seq - _latest`를 무해하다고 잘못 써서 다시 쓰고, 결정적 테스트(65500, 65501, 300, 285, 284)를 더했다. 토폴로지 면접은 호스트의 "지연 0"을 Unity 리슨 서버 페이지("large latency advantage")로 인용하고, 락스텝 대역폭을 Gaffer가 실제로 한 주장으로 고쳤으며, Unity distributed authority에 잘못 붙어 있던 n(n−1)/2를 떼어 냈다. Photon 관련 진술은 일치했고 귀속을 밝혔다.

**끝까지 확인하지 못한 것.** 남은 항목은 없다. 토폴로지 면접 해설은 2,462자다.

**무엇을 만들었는지.** 헤더 6바이트로 최근 33개 패킷의 도착을 알리는 ack 비트필드, 예측·재조정·시각 보정 버그 세 개 디버깅, 1D 클라이언트 예측과 서버 재조정, 틱 레이트·전송률·보간 지연 과외, 락스텝·스냅샷 보간·상태 동기화 선택 면접, 지터 버퍼의 6문제다(2/2/2). 작성 단계 check-tests는 모든 해답 통과, 시작 코드 0 통과였다. 작성자는 Gaffer, Gambetta II·III, RFC 3550, GGPO README, MS Learn 시프트·산술 연산자를 원문으로 읽었다(Valve 위키는 봇 차단 때문에 인용하지 않았다). 지터 버퍼의 ×3 목표·2 ms 단계·64 창과 디버깅 문제의 2 m 스냅 임계값은 문제 자체의 규칙으로 표시했다. 커밋 `2725cf6`으로 배포했다.

**검수에서 확인한 것.** Gaffer(신뢰성, 결정론적 락스텝, 스냅샷 보간, 상태 동기화, 게임 네트워킹 개요), Gambetta II·III, GGPO README, RFC 3550 §6.4.1·A.8, Microsoft Learn(시프트 연산자, 산술 연산자)을 열었다. ack 비트필드의 비트 배치, ack 33개, 1초 손실 규칙, `sequence_greater_than`은 Gaffer 원문과 일치했고, 제목의 "6바이트"가 ack 2 + ackBits 4라는 설명만 보탰다. 예측 디버깅은 버그 조합 8가지 중 완전한 수정만 통과했다. 지터 버퍼의 RFC 3550 공식 인용은 정확했다.

**틀려서 고친 것.** 예측 디버깅의 QA 보고 1과 버그 1 해설은 서버 응답이 올 때마다 튄다고 했지만, 시뮬레이션해 보니 버그 1은 한 스텝 앞선 상태가 계속되는 것이라 첫 응답 때 한 번 뛰고 멈추면 돌아온다. 두 글을 다시 썼다. c7이 제약에 없던 캡처 람다를 깎고 있어 제약을 넣고 클로저 언급을 일반 C# 지식으로 표시했다. 1D 예측은 Easy로 잡았지만 실제로는 Medium이어서, 시작 코드가 예측·전송 절반과 순진한 덮어쓰기를 제공하고 학습자는 `Reconcile`(약 6줄)만 쓰도록 범위를 줄였으며, 시나리오·제약·힌트·경계 사례·c1/c2/c5/c10–c12를 다시 썼다. 틱 레이트 과외는 (N+1)×간격 규칙과 50/50/35 ms 여유를 세 가지 가정을 둔 이 연습의 모델로 밝혔고, 퀴즈와 해설의 "조금 늦은 패킷이 50 ms를 통째로 멈춘다"는 틀려서 고쳤으며, d1의 근거가 안 되던 인용을 정리했다. 동기화 모델 면접은 `sourceRefs`를 5개에서 4개로 줄이며 개요 글을 뺐고, 그 글에 기대던 주장(RTS·Quake 역사, 늦은 합류)과 롤백 비용 주장을 일반 지식이나 추론으로 표시하고 특정 게임 이름을 지웠다. 지터 버퍼는 `next + 64` 프레임을 받아들이는 답이 모든 테스트를 통과해 이를 잡는 결정적 케이스를 넣었고, c9의 `long` 요구를 제약에 적었다.

**끝까지 확인하지 못한 것.** 동기화 모델 면접은 꼬리질문이 깊어 Medium 경계에 있지만 난이도 배분을 위해 그대로 두었다.

**무엇을 만들었는지.** 클라이언트가 확인한 기준 스냅숏과의 차이만 보내는 델타 압축, 순서 뒤바뀜·중복 메시지에 깨지는 로비 상태 기계 디버깅, 지터는 견디고 속도 핵은 막는 서버 이동·쿨다운 검증, 매치메이킹·세션·재접속 면접, JSON·고정 바이너리·TLV 전송 형식 과외, HTTP/REST·WebSocket·UDP 배치 면접의 6문제다(2/2/2). 작성 단계 check-tests는 해답 8/8, 시작 코드 0/8·2/8·0/8이었다. 작성자는 규칙마다 그 규칙을 뺀 변이 약 30개로 확인했고, 로비 버그는 각각 따로 실패하며 시나리오의 증상은 버그 코드의 실제 출력이다. 과외와 면접은 `tests: null`이다. 브라우저가 UDP 소켓을 열 수 없다는 것, 백오프, 구매 ID, 세션 세대 펜싱은 처음에 일반 지식으로 표시되었다. 커밋 `0ac11ed`로 배포했다.

**검수에서 확인한 것.** protobuf 인코딩과 proto3 페이지, RFC 9110·6455·8259·9220, Boss Room SessionManager.cs(인용한 커밋), PlayFab 문서 다섯 쪽, Unreal 5.9 네트워크 이동 페이지, Gaffer 세 편, Gambetta, Wikipedia 세 쪽, GPP, Learn과 Azure 여섯 쪽, MDN 세 쪽, Kleppmann의 글을 열었다. 델타 압축은 확인받지 않은 기준을 쓰는 변이와 다른 틀린 버전 12개를 잡았다. 로비는 인용된 증상이 시작 코드의 실제 출력과 같고, 버그 하나만 남겨도 실패하며, 부분 수정 넷도 실패했다. 도착 순서 스크립트는 시작 코드에 고정되어 있다. 이동 검증은 틀린 버전 12개를 잡았다. 코드와 템플릿은 바꾸지 않았다.

**틀려서 고친 것.** 델타 압축은 32 스냅숏 이력과 초기 상태로의 재설정이 Gaffer가 아니라 이 문제 자체의 규칙이라고 밝혔다. 로비는 떠난 플레이어 기록도 세어지므로 O(n) 주장을 고쳤다. 이동·쿨다운 검증의 "6T + 1.5 m" 한계는 틀렸다. 받아들인 패킷마다 float 허용 오차가 최대 1 mm씩 더해질 수 있어 고쳤고, 쿨다운 경계 사례에는 0 ms의 이전 사용이 필요했으며, 기준을 뒷받침하지 않던 Unreal 인용을 뺐다. 세션 면접은 PlayFab의 티켓 하나 규칙이 한 큐 안에서만 적용된다는 것, Boss Room의 중복 검사(인용 커밋의 코드)가 세션 데이터를 거부한다는 것을 바로잡았고, 세션 번호는 Kleppmann의 펜싱 토큰으로, 버전 붙은 쓰기는 PlayFab 인벤토리 ETag로 인용했다. 전송 형식 과외는 Last One Wins가 반복되지 않는 필드에만 해당한다고 고치고, proto3 필드 존재 규칙과 LEN 타입 레코드만 길이를 갖는다는 점을 더했으며, JSON 정밀도 답에 출처를 달았다. 프로토콜 면접은 RFC 절 번호와 9110의 재시도 예외를 더하고, 브라우저 UDP 제한을 Unity 6 매뉴얼과 MDN으로, 백오프와 구매 ID를 Azure 지침과 PlayFab IdempotencyId로 인용했다.

**끝까지 확인하지 못한 것.** 검수 보고에 남은 미확인 항목은 없다. 프로토콜 면접의 TCP 멈춤 꼬리질문은 `t8-interview-tcp-vs-udp`와 일부 겹친다.

**틀려서 고친 것.** 지연 보상 문제에 대해, Bernier 논문 원문은 "connection latency"라고만 하고 단방향인지 왕복인지 말하지 않으므로 그렇게 밝히고, 이 문제에서 왕복이 맞는 이유(플레이어가 명령 직전에 받은 업데이트는 명령이 도착하기 약 한 왕복 전의 서버 상태다)를 설명했다. 관심 영역은 과제가 요구하지 않은 것을 묻던 채점 항목 둘 때문에 과제에 그 요구를 넣었고, 허수아비 같던 오해 하나를 Unreal 5.9와 NGO 2.4 페이지가 뒷받침하는 것으로 바꿨다(시작 코드는 Floor를 쓰므로 절삭을 버그라 부르는 글은 없다). AOI 격자의 "방향에 따라 32–64m"는 축 방향에서만 참이어서 고쳤고, Easy를 유지하려고 시작 코드가 딕셔너리 둘과 버킷 도우미를 제공하게 하고 힌트와 채점 항목 하나를 맞췄다. 보안 면접은 세 곳에서 0-RTT가 "재전송을 보장하지 않는다"고 쓴 것을 "재전송되지 않음을 보장하지 않는다"로 고쳤고, "직접 UDP 프로토콜 만들기"만 답이 되지 않도록 DTLS 1.3(RFC 9147)을 넣었으며, netcode 크기 검사 문구를 표준에 맞추고 근거가 안 되던 인용 하나를 뺐다. 락스텝은 해답이 `SubmitChecksum`에서 음수 턴을 받으면 죽어서, 그런 턴은 무시한다는 규칙을 넣고 해답과 참조를 고친 뒤 테스트를 더했다. NextTurn−32에서의 하나 차이 오류가 통과하던 것을 잡는 경계 테스트도 넣었고, FNV 매개변수를 Wikipedia와 IETF 드래프트 -17로 인용했다. 시간 동기화는 δ/2 한계를 본문에서 증명하고(|d₁−d₂| ≤ d₁+d₂, 정확한 타임스탬프와 시계 드리프트 없음을 가정) RFC 문구가 아닌 유도라고 표시했으며(RFC 5905는 Λ = E + Δ/2를 "최대 오차"로 정의할 뿐이다), QPC 진술은 Windows 전용으로 표시했다.

**끝까지 확인하지 못한 것.** 검수 보고에 남은 미확인 항목은 없다. 1500 Archers 글은 페이지가 Paul Bettner만 밝혀 그렇게 표기했다. 디버깅과 락스텝 해설은 추가된 절 때문에 약 1,900자다.
